# 手動操作と模擬エージェント提案の比較

基準コミット: `d6f4c1ea52f279ab5a381563cfc469d868f9f080`、Draft PR #13。以下はローカル検証の記録。レビュー用の反映先は既存専用ブランチとDraft PR #13。最終SHA・CIはPRに記録する。既存の読みやすさ改善を保持して検証した。実AI・実認証・共有DB・外部3Dは未接続。本番公開・mainマージ・手動デプロイは行わない。

## 比較条件

実Chromium、PC 1440×1000／スマホ幅390×844、同じ合成入力・初期サンプル。外部通信を遮断し、WebMCPホストと質問応答を模擬した。エージェントには完成した構造化入力をテストから渡す。自然文の目的入力、LLMの推論・質問能力、入力準備、実モデルの待ち時間・費用は測定していない。

UI回数はスクリプト内のクリック・選択・入力・確認を各1回と数える。スクロール、読解、迷い、入力文字数、ツールの準備、検証用の状態読取りは含まない。ツール呼出し数は別記。自動処理の時間には通信待ち・テスト実行待ち・同時検証のCPU負荷が含まれ、初見ユーザーの所要時間でも時短効果でもない。時間の生値はJSONにのみ保存し、優劣や削減率の根拠に使わない。

| 目的・同じ入力 | 共通の成功条件 |
| --- | --- |
| 経路と根拠を確認: 車椅子世帯、水害、雨、昼 | 明示承認後の保存経路・距離・目安時間・回避対象が一致し、計算条件・出典・日時・未確認事項と地図を確認できる |
| 天候だけ晴れに修正 | 雨の提案を勝手に実行せず、晴れへの変更後に確認が解除され、再確認後の経路が一致する |
| 「交差点の道路が浸水しています」を保存 | 地点35.6813,139.7611、分類・条件・本文・確かさ・報告種別が一致し、確認票を代行しない |

手動の経路画面は基準経路と情報反映経路の2本を比較する。既存エージェントツールは情報反映経路1本を保存する。上表ではその1本と根拠の確認を比較し、エージェントが2本比較を行えたとは評価していない。観察のエージェント入力は既存の手動プレビュー関数が生成した値であり、モデルの解釈精度を検証したものではない。ID・生成時刻を除く保存内容の一致をassertした。

## 発見と最小修正

1. 改善前のエージェント完了画面には計算根拠がなく、最初の成功条件を満たせなかった。実ツールの完了結果だけを表示し、依頼時に取得済みの出典・更新日時・未確認事項を追加した。地図表示は保存経路と結果が一致するときだけ許可し、変更・削除後は歴史的記録として区別する。
2. 提案の天候だけを修正する導線がなく、別提案の用意に依存した。「この条件を手動で直す」は先に当該依頼を取消し、条件だけを既存の入力画面へ渡す。質問開始・修正・新しい本人確認が必要で、自動API／ツール実行や承認の継承は行わない。
3. 観察提案が英語enumのJSONだけだった。既存翻訳と既定値ルールによる日本語要約を追加し、正確な入力JSONも残した。独立レビューでincident既定値の表示不一致が1件見つかり、既存defaultReportTypeで修正。観測時刻省略時の保存動作も表示・回帰検証した。

## 後日の人間・iPhone確認（短い手順）

初見の人に順に次の目的だけを渡し、使い方を先に教えず、開始から完了までの時間・タップ数・迷った箇所・失敗／助けが必要だった箇所を記録する。個人情報は架空にし、実AIを使わない。手動と提案画面の実施順は交互にする。

- 車椅子の家族、水害、雨、昼で訓練し、根拠と未確認事項を説明して地図を開く。
- 提案の雨を晴れに直し、再確認して計算する。取消と再確認が分かったか確認する。
- 合成の浸水観察を保存し、地点・種別・共有保存の有無を説明する。

iPhone実機ではキーボード表示、拡大文字、縦横回転、VoiceOver、戻る／再訪、動きを減らす設定でも確認する。今回の390×380は縮小viewportによるキーボード領域の模擬で、実OSキーボードではない。人の結果が得られるまで速度・理解度の改善を断定しない。
